# 我用 [SYSTEM] 还原了一对清代婚姻：一次完整流程的白话讲解

> 本文用普通话把上一篇 [`case_study_mas_negotiation_log.md`](case_study_mas_negotiation_log.md) 里发生的事情**重述一遍**，避免技术行话，让没接触过系统的人也能按图索骥。研究背景：清代家谱（jiapu）里女性记录大面积缺失，我们要做的就是「把谁嫁给了谁」从破碎的家谱里**反推回来**。

---

## 故事背景：要解决什么问题

**真实场景**：一本 19 世纪的家谱里写着「张某某，娶妻王氏」——只剩一个姓。她是哪一户的王？没说。

**我们的玩法**：找一份*完整记录的*清代户籍数据 (CMGPD-LN，1882 年辽宁的人口册)，把里面的婚姻配对**人为地藏起来**，假装家谱那样残缺，然后试着用机器学习+大模型把它**猜回来**。猜对了多少，对照真值就一目了然。

**今天的具体小目标**：1882 年那份户籍里，一位叫 **P89414** 的男性 (49 岁，住辽宁北部) 应该娶了谁？后台真值是 **P92557** (33 岁)。我们装作不知道，看看系统能不能找回来。

---

## 第一步：在 V3「蜂巢图」里随便点一格

### 我看到什么

V3 是仪表板的"全队列地图"。1882 年这一年所有候选婚姻被压成 6000 个小点，再聚成 **288 个六边形格子**，按颜色排：
- **绿色格子** = 系统对这格里的配对很有把握（"我觉得它们多半是真的"）
- **红色** = 系统觉得这格里多半不是真的
- **米黄** = 不确定

### 我点了什么

我挑了**最绿的那个格子**——cell 106，颜色 `#0f6e56` 浓绿，意思是"这里面的配对极可能正确"。

### 系统的反应

我点击的瞬间，V3 的格子一变：
- 选中的那一格被勾出黑边
- **其他 287 个格子**全部褪色到 18% 的不透明度，让我能盯紧选中的这一块
- V3 通过一条内部"广播信道"告诉 V4 / V5 / V6：「用户选了这堆配对，请展示」

---

## 第二步：V4 自动展开，画出双方关系

V4 收到 V3 的广播后立刻重绘。原本是空白的，现在变成一张二部图：

- **左边一列**：7 位男性的 ID
- **右边一列**：12 位候选女性的 ID
- **中间**：12 条贝塞尔曲线连接它们，每条线上印着 HGT 模型给这个配对打的分

我看到的分数从 6.62 到 7.99 不等——**全是高分**，进一步证实这是个"系统有把握"的格子。

---

## 第三步：点击男性 P89414，弹出他的资料

我点 V4 左上角的 **P89414** 圆点。一个小卡片浮出：

| 项目 | 值 |
|---|---|
| 性别 | 男 |
| 出生年 | 1833 |
| 八旗 | — *（这位男性的八旗记录确实空缺）* |
| 区域 | 辽宁北部 |
| 社区 (村) | 252 |
| 户号 | 9183702103 |

**P89414 在 1882 年正好 49 岁**，属于队列里的中年成婚者。

同时 V4 又通过广播告诉 V5：「请把这位男性载入辩论场」。

---

## 第四步：V5「辩论场」启动六轮博弈

V5 是这套系统的核心，也是大模型登场的地方。它把 P89414 和 6 位候选女性 **分别**做成 7 个 LLM 智能体（每个智能体读取自己档案里的真实生平 + 收入流水），然后让他们**互相对话、互相评分**。

我按下 V5 的 `▶ arena` 按钮。

### 六轮博弈的设计

每轮有不同主题：

| 轮次 | 主题 | 比喻 |
|---|---|---|
| R1 | persona | 「先各自做个自我介绍」 |
| R2 | 第一印象 | 「你看着合适吗？" |
| R3 | 深度对谈 | 「咱俩价值观对不对？」 |
| R4 | 反诘 | 「等等，你刚才说的这一点我有疑问」 |
| R5 | 长期相容 | 「往后过日子能磨合吗？」 |
| R6 | 决断 | 「公式打分排序」 |

每轮结束都需要**我手动点 "Approve & Advance →"** 才能继续——这一刻还可以通过 `@everyone` / `@target` / `@c-{id}` 的提示框给某位智能体打补丁（譬如告诉所有人"这个家有过妻子姓王的记录"）。

---

## 第五步：六轮博弈的真实经过

**重点**：每个候选最后都拿到两个分数 —— `t` (男方给候选打的分) 和 `c` (候选给男方反向打的分)。系统看重「双方都觉得对方好且彼此意见接近」。

我直接展示每一轮男方对真实妻子 P92557 (16 岁年龄差，与 P89414 同村 252) 和**最容易被搞混的那一位** P93553 (21 岁年龄差) 的态度变化：

### 第 1 轮 (persona)
两位智能体各自做自我介绍，没人给对方打分。

### 第 2 轮 (第一印象) ← **关键时刻**
- **P92557**：男方打 t=5（全场最高），女方反打 c=7。最终分 5.4。
- **P93553**：男方打 t=4，女方反打 c=5。最终分 4.2。
- **MAS 已经把真实妻子排到第一**，差距 1.2 分。

男方对 P92557 的评语原话：
> "Closest age match at 16 years, shares core values, but prior marriage history requires clarification."
> （年龄最接近、价值观共享，但他过去婚姻经历需要确认）

男方对 P93553 的评语原话：
> "21-year age gap exceeds ideal 0-5y range; prior marriage exposure warrants scrutiny despite shared values."
> （21 岁年龄差超出理想区间，他过去的婚姻经历需要审视）

### 第 3 轮 (深度对谈) ← **危险时刻**
深度对谈的主题是"价值观和家庭契合"，结果让两位候选都被**大幅上调**：
- **P92557**：t 升到 8，最终分 7.2
- **P93553**：t 也升到 7，最终分 7.2
- **两人并列**，MAS 暂时**无法分辨**

LLM 在"找共同点"模式下会过度乐观——P93553 的 banner-4 突然被解读为"和我的香火大目标兼容"，于是分数飞起来。

### 第 4 轮 (反诘) ← **拯救时刻**
反诘主题是"挑刺"，于是 6 个候选**全部被下调 1 分**——男方意识到自己刚才太乐观了：
- **P92557**：回落到 t=7，最终分 7.2 (基本不变)
- **P93553**：回落到 t=6，最终分 6.0 (-1.2)
- 真实妻子**重新拉开 1.2 分领先**

反诘焦点把 R3 的过度共识硬掰回来。这正是「多轮交替不同主题」的设计目的：单一焦点会让 LLM 系统性偏差累积，多焦点交替能让乐观和悲观相互抵消。

### 第 5 轮 (长期相容) ← **趋于稳定**
长期相容主题让所有人的态度回归冷静。P92557 t=5 (跟 R2 一样)，P93553 t=4。最终分：
- **P92557：5.4**
- **P93553：4.6**

差距 0.8 分。

### 第 6 轮 (决断)
不再调用大模型，直接按公式 `分 = (t+c)/2 - 0.3·|t-c|` 排序。结果：

| 名次 | 候选 | t | c | **最终分** | 对应真值 |
|:---:|---|:---:|:---:|---:|---|
| **1** | **P92557** | **5** | **7** | **5.40** | ✓ **真实妻子** |
| 2 | P93553 | 4 | 7 | 4.60 | ✗ |
| 2 | P165718 | 4 | 7 | 4.60 | ✗ |
| 4 | P69317 | 3 | 7 | 3.80 | ✗ |
| 4 | P165701 | 3 | 7 | 3.80 | ✗ |
| 6 | P175690 | 3 | 6 | 3.60 | ✗ |

---

## 第六步：我点击「accept」，看见五个视图同时变化

我在 V5 上点下 P92557 卡片的 `accept` 按钮。系统在 1.5 秒内把这个决定**广播到全部视图**：

### V1（学习曲线）的反应
原本曲线在 0 处。一接受 → 曲线在 x=1 处跳到 y=1.0。屏幕显示：
```
ablated · 1 accepted · 1/1 correct · MAS=1.000
```
**1/1 correct** 是真值核对：P92557 确实就是 P89414 的真实妻子（HGT 自己排第二、Hungarian 也错了，但 MAS 把它捞出来了）。

### V2（已处理关系表）的反应
表格新增一行：
```
husband=P89414  wife=P92557  score=5.00  gap=-0.02  source=[MAS]  [↶ restore]
```
**source 标签只挂了 MAS，没有 HGT 标签**——系统通过这个细节告诉我：「这个决定 HGT 不同意，是 MAS 凭对话改的」。这种"两条管道意见不一致且 MAS 最终对了"的案例，在标签上一目了然。

### V3（蜂巢图）的反应
代表 P89414-P92557 那个点被**遮蔽**——意思是「这条边已经定案，不要再让我点了」。

### V4（双方关系图）的反应
P89414 ↔ P92557 那条边变暗。

### V5（辩论场）的反应
P92557 的卡片获得绿色光晕（`pick` 状态）；其他 5 张候选卡变灰。

### V6（亲属网络图）的反应
显示 P89414 + 6 位候选的一阶亲属节点；接受后 P92557 与 P89414 之间画一条新的"婚姻边"，其他 5 位候选所属的亲属子图整体变暗。

---

## 这件事说明什么？三个白话结论

### 1. HGT 几乎答错了，但只差一根头发丝

HGT 给的分数是这样的：
- P93553 (错的) = **8.4819 logits**
- P92557 (对的) = **8.4663 logits**

差距只有 **0.0157 logits**。这个差距比 HGT 模型分辨率本身还小。如果只看 HGT 第一名，会选错。

### 2. MAS 把这根头发丝放大了 50 倍

MAS 经过六轮博弈后给的分数是：
- P93553 = 4.60
- P92557 = **5.40**

差距 **0.80 final score**——是 HGT 上原差距的 **51 倍**。MAS 不是更聪明，而是把"聊天里能透露的细节"都问了出来——年龄差、社区是否相同、对方对自己缺点（"banner 不详"）的反应，等等。

### 3. 多轮主题轮换是关键，不是六轮越多越好

回顾每轮真实妻子和 HGT 错首选之间的差距：

```
R2 第一印象:    +1.2  ← MAS 一开始就分得出
R3 深度对谈:     0.0  ← 危险！差点并列
R4 反诘:        +1.2  ← 拉开领先
R5 长期相容:    +0.8  ← 稳住
R6 决断:        +0.8  ← MAS 选 P92557 (对)
```

**R3 是个坑**——大模型在"找共识"模式下会乐观地把所有人都推高，让真实和虚假并列。**R4 反诘救场**——焦点切换到"挑刺"，把 R3 的过度乐观纠正回来。

如果我们只设一种主题，MAS 要么过度乐观（错认）要么过度悲观（错杀）。**主题轮换**让两类系统性偏差互相抵消，最终的真实妻子在「整个回合体系下」表现最稳。

## 实际操作中的几个要点

| 用户操作 | 在哪个视图 | 系统反应 |
|---|---|---|
| 点击一个绿色 hex | V3 | V4 自动展开二部图 |
| 点击男性圆点 | V4 | 弹个人资料卡 + V5 装载该男性 |
| 关掉资料卡，按 ▶ arena | V5 | 启动六轮博弈，第一轮 personas 出现 |
| 等大约 5 分钟后点 Approve & Advance | V5 | 进入下一轮，每轮 LLM 推理需 3-5 分钟 |
| 想干预？输入 `@everyone wife's surname is Wang` | V5 hint console | 下一轮的 prompt 里会带上这个提示 |
| 觉得已经够了，点候选卡的 accept | V5 | V1 / V2 / V3 / V4 / V6 同时刷新 |
| 发现错了？点 V2 行末的 ↶ restore | V2 | 全部视图回滚，曲线、表行、点遮蔽都恢复 |

整个会话从我点击第一个 hex 到 V6 出现婚姻边，**实际耗时约 25 分钟**（其中 20 分钟是六轮 LLM 推理）。

---

## 一句话总结

**系统的核心价值是这一句**：HGT 给出"差距小于 0.02 logits"的两个候选，单看模型自己几乎是抛硬币；让六位 LLM 智能体替双方"过日子般地"对话四轮，系统能把这条边的分辨率拉大 50 倍——而且我（人）随时可以在中间插一句话改方向。

它不是更准的 ML 模型，而是一种**让人和模型轮流说话**的工作流——既保留了 HGT 的覆盖能力（300 多个 hex 一眼可见），又让大模型用自然语言把"为什么这两个看起来都行的候选其实不一样"说出来，最后由我审议、决断、可撤销。

而所有这些过程都被 V2 的 source chip + V1 的曲线 + V6 的亲属边**全程留痕**——任何一个决定都能查回是谁、什么时候、依据什么提交，并能一键 restore 重来。
